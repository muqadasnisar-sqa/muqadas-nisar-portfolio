🔄 Software Testing Life Cycle (STLC)

How I Guarantee Release Quality

My structured 6-stage QA methodology ensures every feature is validated from requirement gathering and Figma design specs to API load testing and production release sign-off.

STAGE 01 • REQUIREMENTS & FIGMA

SRS Review & Figma Design Parity

Analyze SRS/PRD documents, user stories, and Figma mockups to identify edge cases, missing validation rules, and UI/UX discrepancies before development concludes.

STAGE 02 • TEST PLANNING & DESIGN

Test Suites, EP, BVA & Traceability

Author comprehensive Test Plans, Requirement Traceability Matrices (RTM), Equivalence Partitioning (EP), and 6-point Boundary Value Analysis (BVA) test cases.

STAGE 03 • FUNCTIONAL & MULTI-PORTAL UI

Web, Mobile, Admin & Cross-Browser QA

Execute Smoke, Sanity, Functional, and Responsiveness testing across Customer Web, iOS/Android Mobile Apps, Admin Dashboards, Kitchen, and Driver portals.

STAGE 04 • API, PERFORMANCE & SQL

Postman API, JMeter Load & DB Audits

Validate REST API status codes, JSON schemas, and response SLAs in Postman, run load/stress tests via Apache JMeter, and verify database integrity using SQL JOINs.

STAGE 05 • DEFECT TRIAGE & LIFECYCLE

Reproducible Bug Reporting in Jira

Log clear, developer-ready bug reports with Severity & Priority (`S1–S4 / P1–P4`), ordered Steps to Reproduce, HAR network traces, console logs, and video evidence.

STAGE 06 • REGRESSION & AUTOMATION

Full Regression & Playwright Sign-Off

Re-test resolved defects, execute end-to-end regression suites and Playwright automation scripts, and deliver formal QA Release Health Sign-Off.
